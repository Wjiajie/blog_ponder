> 图形学/特效渲染背景转 FDE（教育方向）的 6 个月路径。我会持续在这里补充OpenAI/Anthropic/Google Cloud FDE 等公开 JD 信号、准备情况和面试经验。

## 写在前面

背景：图形学/特效渲染方向开发，熟悉 C++/Python，工程能力有底但 LLM 理论和agent框架了解不多。

目标：6 个月内转型到 AI Native公司的 FDE（Forward Deployed Engineer）团队，方向偏教育。

我想完成这个转型，是基于几个底层判断：

**1. AI有巨大自动化潜力，传统行业掌握大量konw-how经验，FDE是这两者的链接点**

Agent在互联网圈子中证明了它巨大的能力，但细化到具体的很多传统领域，还是欠缺了最后的十公里路的，我认为关键点是，如何把具体行业中复杂的流程自动化，可能是一个千人千面的问题，一个困境是传统领域中的富有经验的人，未必能意识到Agent的能力，以及知道如何以agent为核心重新设计整个工作流。但熟悉Agent架构设计和能力边界的人，又未必懂业务。中间缺少一座桥梁，这就是FDE要干的事儿。

**2. FDE是互联网行业从业者走向AI Native的具体领域创业的简单途径**
作为互联网从业者，我想把AI native的核心能力迁移到其他的传统行业，一个困点在于：我并不具备具体的其他行业的经验，这其实是上述第一个问题的另外一个视角。

## 1. 必备技能图谱

### 1.1 必须掌握（Offer-blocking）

**Python 高级用法**（已有，补 AI 生态）

异步（asyncio）、类型注解、装饰器、上下文管理器。FastAPI 必须，能搭生产级 API。pytest 必须——FDE 要会写自动化测试。

**LLM 基础**（0 基础 → 实战级）

Transformer 原理不要求推导，但要能讲清 attention/token/context window。Prompt 工程：Few-shot、CoT、ReAct、System Prompt 设计。主流模型 API：OpenAI、Anthropic、MiniMax、Mistral 都要摸过。Token 成本与上下文管理——客户问"这套方案花多少钱"时答不上来就直接减分。

**Agent 开发**（最核心）

LangChain/LlamaIndex 至少精通一个。LangGraph 优先级升档——OpenAI/Anthropic JD 都点名要"agentic workflow"经验。Dify/Coze 低代码平台至少体验一个。MCP（Model Context Protocol）——MiniMax JD 明确提到，Anthropic JD 明确要求"交 MCP servers / sub-agents / agent skills"，是 2026 硬通货。编排模式：ReAct、Plan-and-Execute、Multi-Agent、A2A。

**RAG 全链路**

文档加载 → 切片 → Embedding → 向量库 → 检索 → 重排 → 生成。向量数据库：Milvus/Qdrant/Chroma 至少一个生产级。检索优化：BM25 + 稠密检索混合、重排模型、引用溯源。

**LLM 评估**（JD 明确要求）

RAGAS 框架、自建评测集（golden set）、LLM-as-a-judge 校准。v2 引入 4 层评估体系（v1 只覆盖 AI 工程指标）：

| 层级 | 关键指标 |
|---|---|
| 模型质量 | 答案正确率、幻觉率、引用准确率、题目难度匹配 |
| 教学质量 | 是否符合课标、是否超纲、讲解是否符合学生认知水平 |
| 教师效率 | 备课/批改/出题时间减少多少、**老师修改率** |
| 业务结果 | 完课率、续费率、家长满意度、学生错题复发率 |

"老师修改率"（AI 生成 100 道变式题，老师只需轻改 20 道 → 80% 通过率）比"模型准确率 92%"更接近业务语言。

**模型微调（基础）**

LoRA/QLoRA 原理 + 实战（Hugging Face + PEFT）。关键不是会调，而是判断何时该微调、何时该 RAG、何时该换 Prompt——这三种路径的边界是面试必问。

**部署与工程化**

Docker 必须，Kubernetes 基础（Pod/Service/Deployment），CI/CD（GitHub Actions 起步），公有云至少熟悉一个。v2 增补：灰度发布、回滚、监控告警——客户生产环境的标配。

**基础全栈**

前端 React 或 Next.js 基础（能搭可交互 demo），数据库 PostgreSQL + Redis，消息队列 Celery 或 RabbitMQ。

**v2 增补：客户交付方法论**

7 天 PoC / 30 天试点 / 90 天规模化 节奏（见 §5）。客户访谈技巧：先澄清问题、划边界、做 trade-off。ROI 量化：教师节省时间、老师修改率、错题复发率。

**v2 增补：教育 AI 合规基础**

《个保法》《未成年人网络保护条例》《生成式 AI 服务管理暂行办法》核心条款。数据脱敏、最小化采集、家校授权流程。prompt injection / 题库泄露 / AI 内容审核 工程方案。

### 1.2 加分项（差异化）

**多模态**——图形学老本行最直接的发挥点

MiniMax Hailuo 视频生成、MiniMax Speech 语音合成/识别、VL 模型图像理解。三个月前我做过一个 Hailuo 视频生成的内部 demo，效果超预期。

**AI Coding 工具深度使用**（JD 明确提到）

Claude Code / Cursor / Codex / Cline，不只是用，要能讲清"AI Coding 的上下文管理"原理。v2 增补：能列出 10 类 AI 写错模式（见 §4.1）——ChatGPT 在 review 时让我现场列举，我卡住了 3 个，这是 v1 的真实盲区。

**3D / 实时渲染 + LLM**（差异化）

Three.js / WebGL / Unity + LLM Agent，可做"AI 生成的 3D 教学场景"。v1 措辞是"FDE 团队里**只有我**能把'图形学 + LLM'打通"，ChatGPT 指出这话在面试中用力过猛。v2 改为："差异化优势是把图形学、实时交互、多模态 LLM 结合到教育场景里，能交付普通 AI 应用工程师不容易交付的沉浸式体验。"

**开源贡献**（JD 加分项：1000+ stars）

不一定要 1000 stars，但持续贡献是关键。计划把 3 个项目的工程 drill 仓库全部公开，加上"AI 写错模式"笔记。

**教育行业认知**（v2 升为必备）

5 类细分客户（K12 校内 / 教培机构 / 职教 / 高校 / 教育 SaaS）的买单方、痛点、AI 落地难点各不相同。见 §7。

## 3. 三个项目：1 旗舰 + 1 差异 demo + 1 轻 case study

> **v2 重大修订**：v1 的错题讲解与学情诊断两个项目功能流强耦合（错题讲解必然涉及诊断，分层作业必然涉及讲解），合并为 1 个旗舰项目；3D 实验室转为差异化能力展示；新增 1 个轻量 case study。

### 项目 1（旗舰）：AI 错题诊断与分层作业助教系统

**痛点**：

老师批改 60 份作业后为每道错题手写讲解，周日晚 8 点开始、平均耗 6 小时，占课后服务时间 40%。班级授课无法真正分层，70% 学生做题是"会的反复做，不会的没练到"。错题讲解依赖老师个体经验，新老师上手慢，资深老师时间被挤压。

**方案**（完整闭环）：

```
错题输入（图片/拍照/手写）
   ↓
[知识点识别 + 错误归因] — M-Text-01 + RAG 查询校本题库
   ↓
[生成讲解] — 文字 + 配图（M-VL-01）+ 语音（M-Speech）+ 知识图谱关联
   ↓
[生成变式题] — 难度梯度 P20/P60/P80，teacher approval workflow 必须介入
   ↓
[分层作业包] — 按学生学情图谱差异化推送
   ↓
[学情 dashboard] — 班级整体薄弱点、个体学情曲线
   ↓
[家长简报] — 每周一次自动生成，必须经老师审核
```

**技术栈**：

- 后端：FastAPI + LangGraph（多步 Agent + 状态管理）+ Milvus
- 前端：Next.js + shadcn/ui
- 多模态：MiniMax M-Text-01 / M-VL-01 / Speech / Hailuo
- 评估：RAGAS + 自建 golden set + 4 层评估体系
- 部署：Docker + 阿里云函数计算
- 合规：数据脱敏 + 家校授权 + 第三方传输加密

**评估指标**（4 层）：

| 层级 | 关键指标 |
|---|---|
| 模型质量 | 答案正确率、幻觉率、引用准确率、题目难度匹配度 |
| 教学质量 | 是否符合课标、是否超纲、讲解是否符合学生认知水平 |
| 教师效率 | 备课/批改/出题时间减少多少、**老师修改率** |
| 业务结果 | 完课率、续费率、家长满意度、学生错题复发率 |

**M4 末交付物**：MVP + demo + 4 层评估报告 + 2-3 个老师试用反馈 + 1 篇博客

### 项目 2（差异 demo）：AI 3D 沉浸式学习场景

### 4.3 业务场景面：5 个客户场景题（v2 大改）

#### 标杆题（必背）：50 人教培机构的 2 周 PoC

> "一家 50 人教培机构，2 万道历史题库，1000 名学生错题数据，老师每周花 8 小时做分层作业。老板要 2 周内看到 AI 效果。你怎么排 PoC？"

**回答结构**（4 步法）：

1. **目标 / 范围 / 数据盘点**（5 min）
   - 目标：2 周内给老板"看得到"的效果（不是"用得好"，是"看得到"）
   - 范围：只做 1 个学科（如数学）、1 个高频场景（错题讲解 + 变式题）
   - 数据盘点：先看 2 万道题库质量（脏数据比例）、1000 学生错题数据是否完整
2. **高层架构**（10 min）
   - 画图：学生错题 → 错题识别 → 知识图谱 → RAG 检索 → 讲解生成 → 变式题 → 老师审核 → 学生端
3. **关键模块深挖**（25 min）
   - 切分策略：按学科 + 知识点分层
   - 模型选择：M2.5 或 M-Text-01（中文教育场景）
   - 评估：教师小样本打分（5 个老师评 50 道题）
   - 老师审核：teacher approval workflow 必须有
   - 数据安全：学生错题是否出内网？是否脱敏？
4. **权衡 & 风险**（10 min）
   - "为什么不直接长上下文？"——成本 + 速度 + 引用溯源
   - "为什么不微调？"——2 周时间不允许 + 数据量不够
   - "客户预算是多少？"——按 SaaS 报价：1 万/月（看具体功能）
   - "如果客户说效果不好怎么办？"——Day 5 收集 bad case 快速迭代

#### 其他 4 个场景题

**场景题 2：客户数据不能出内网**

> "客户（重点高中）要求所有学生数据 100% 不出学校内网，外部 API 只能用脱敏后的聚合数据。怎么设计？"

混合云架构：RAG 索引放内网，模型推理放内网（Qwen2.5-7B 本地化部署）。第三方 API 只接"非敏感场景"（如通用知识问答）。数据脱敏：错题图片去人脸、文本去姓名/学号。所有 AI 生成内容必须老师确认才能给学生。

**场景题 3：开学季 10 万学生并发**

> "开学季第一天，10 万学生同时登录 AI 助教系统查错题，推理服务怎么设计？"

容量规划：按 P95 延迟 2s、单次推理 1-2s、QPS 估算 → 至少 100 QPS 起步。缓存层：热门错题讲解用 Redis 缓存（命中率 60%+）。异步队列：图片 OCR / 视频生成走 Celery 异步。灰度发布：先 10% 流量 → 50% → 100%。降级策略：推理服务挂了 → 降级到"老师预先准备好的讲解库"。

**场景题 4：客户 push back 你坚持的技术选型**

> "客户 IT 团队坚持要你用 Java + Spring Boot 写后端（不是 Python + FastAPI），你怎么 push back？"

先理解客户真实诉求：是因为团队维护成本？是因为合规？是因为历史系统？不直接 push back 技术选型本身，而是讲"目标"和"trade-off"。如果客户坚持，给出折中方案：用 Java 重写关键路径 + 保留 Python 做 AI 部分（gRPC 调用）。FDE 的核心能力之一是"翻译"，不是"坚持"。

**场景题 5：失败 case**

> "讲一个你做 AI 项目失败的案例，反思学到了什么？"

准备 1 个真实失败案例（哪怕是 M2 阶段的小 demo 翻车）——"我做了一个 RAG 问答机器人，上线后发现某个切片策略导致 50% 答案有幻觉。反思的 3 件事：① 切分前没做内容质量过滤；② 评估集没覆盖边缘 case；③ 上线前没做小流量灰度。"

## 5. 交付方法论（v2 新增专章）

> v1 没有这一章。FDE 面试必考"客户场景题"——给 1 个模糊客户需求，看你能不能拆成可执行方案。FDE 面试官想听的是"7 天 PoC / 30 天试点 / 90 天规模化"的节奏，不是技术栈罗列。

### 5.1 7 天 PoC 模板

> 目标：1 周内给客户"看得到"的效果。

| Day | 任务 | 交付物 | 关键风险 |
|---|---|---|---|
| Day 1 | 客户访谈 + 数据盘点 | 1 页访谈纪要 + 数据质量报告 | 客户配合度不够 |
| Day 2 | 定义 1 个高频工作流 + 写 PRD | 1 页 PRD | 范围蔓延 |
| Day 3 | 接入样例数据 + 跑通数据流 | 数据流图 + 脏数据处理脚本 | 数据格式不一致 |
| Day 4 | 做 RAG / Agent MVP | 能跑通的 demo | 技术选型错误 |
| Day 5 | 老师试用 + 收集 bad cases | 20+ bad case 清单 + 老师口头反馈 | 老师没时间 |
| Day 6 | 补评估 + 调 prompt / workflow | 评估报告 | 评估指标不量化 |
| Day 7 | Demo + ROI 复盘 + 下一阶段 SOW | Demo 视频 + 1 页 ROI 报告 + 30 天试点 SOW | 客户期望管理 |

**Day 1 客户访谈必问 5 个问题**：

1. 您最想解决的 1 个痛点是什么？（不是 3 个，**只问 1 个**）
2. 这个痛点现在怎么解决？耗多少时间/钱？
3. 如果我们能帮您省一半时间/钱，您愿意付多少？
4. 哪些数据您能提供给我？哪些绝对不能给？
5. 2 周后您想看到什么？（**期望管理**）

### 5.2 30 天试点模板

> 目标：3-5 个老师真正用起来，验证"用得好"。

- **范围**：只做 1 个场景（如错题讲解 + 变式题），不扩展
- **用户**：3-5 个老师（不要 50 个，控制试错成本）
- **机制**：
  - 每周收集 bad cases（老师主动标 + 我主动抓日志）
  - 每周出 1 份 eval report
  - 统计教师节省时间（实测：让老师记时间）
  - 统计老师修改率（AI 生成 100 道变式题，老师只需轻改 20 道 → 80% 通过率）

### 5.3 90 天规模化模板

> 目标：从 3-5 个老师扩到 30-50 个老师 + 多班级 + 多学科，建立可持续运营机制。

- **范围**：多班级、多老师、多学科（**但每个学科仍只做 1 个高频场景**）
- **机制**：
  - 权限设计：多租户 RBAC（老师只能看自己班级数据）
  - 日志审计：所有 AI 生成内容有 trace，可追溯
  - 成本控制：按调用量/班级数做预算预警
  - 集成：和教培题库/LMS/飞书/企微集成
- **运营**：
  - 建立老师审核和运营机制（teacher approval workflow 标准化）
  - 培训材料：新老师 5 分钟上手
  - 客户成功：每周一次客户同步会

## 6. 教育 AI 合规与安全设计（v2 新增专章）

> v1 完全没考虑这块。教育 AI 不是普通 B 端工具，碰到学生数据、未成年人、作业图片、学习轨迹、家长沟通记录，合规风险会很快冒出来。3 个项目 README 必须写清这些。

### 6.1 核心法规

| 法规 | 生效日期 | 关键约束 | 来源 |
|---|---|---|---|
| **《个人信息保护法》** | 2021-11-1 | 合法、正当、必要、诚信原则；最小化采集 | 国家网信办 |
| **《未成年人网络保护条例》** | 2024-1-1 | 网络产品/服务提供者、个人信息处理者要履行未成年人网络保护义务 | 国务院 |
| **《生成式人工智能服务管理暂行办法》** | 2023-8-15 | 内容安全、歧视防范、知识产权、个人信息权益、透明度、准确性 | 国家网信办等 7 部门 |
| **《"AI+教育"行动计划》** | 2026（教育部） | 内容安全、技术安全、数据安全、算法安全、伦理安全 | 教育部 |

### 6.2 3 个项目 README 必含的 10 项合规设计

1. **学生数据是否脱敏**（错题图片去人脸、文本去姓名/学号）
2. **是否需要家校授权**（用错题前家长是否签字）
3. **图片、语音、作业文本是否会传第三方模型 API**（走哪条链路、是否加密）
4. **如何做最小化采集**（只采集必要的错题，不采其他学习行为）
5. **如何删除数据**（学生毕业/转学后 N 天内删除，家长可申请删除）
6. **老师、学生、家长、管理员的权限边界**（RBAC 设计）
7. **AI 生成内容是否需要老师审核**（teacher approval workflow 必含）
8. **错题讲解错误时谁负责**（明确责任划分，不能让 AI 背锅）
9. **如何防止学生过度依赖 AI**（产品层 + 教学层双重限制）
10. **如何处理 prompt injection 和题库泄露**（输入过滤 + 提示词分层）

### 6.3 4 类教育 AI 合规边界

```
数据边界 ─── 学生数据采集范围
            ├─ 必要数据：错题/题目/答题记录
            └─ 非必要：人脸/家庭住址/父母职业

传输边界 ─── 数据是否出内网
            ├─ 公办学校：原则上不出内网
            ├─ 教培机构：可出但需脱敏
            └─ 教育 SaaS：看合同条款

内容边界 ─── AI 生成内容谁能看
            ├─ 老师：所有内容
            ├─ 学生：经老师审核的讲解
            └─ 家长：每周简报

责任边界 ─── AI 出错时谁担责
            ├─ 老师必须审核后才能发布
            ├─ 平台：提供审核工具 + 风险提示
            └─ AI 模型：作为辅助，不背最终责任
```

### 7.2 教育行业分层（v2 升级：5 类细分客户）

> v1 按学段分（K12/高教/职教/成人），缺"买单方+AI 落地难点"——FDE 谈 ROI 必须能讲清这两点。

| 细分场景 | 买单方 | 核心痛点 | AI 落地难点 |
|---|---|---|---|
| **K12 校内** | 学校 / 教育局 / 集团校 | 教师减负、因材施教、治理 | 采购慢、合规严、数据割裂 |
| **教培机构** | 校长 / 运营负责人 | 提升续费、降低教研成本、稳定教学质量 | 预算敏感、见效要快 |
| **职教** | 学校 / 实训中心 | 实训、技能训练、虚拟仿真 | 内容专业、系统集成重 |
| **高校** | 院系 / 教师 / 信息化部门 | 助教、科研、课程建设 | 场景分散、价值评估难 |
| **教育 SaaS** | 产品/技术负责人 | 把 AI 嵌进现有产品 | API、权限、成本、稳定性 |

#### 6 个月内的 beachhead 选择

> 未来服务中小教育公司和机构，beachhead 不建议选"公办 K12 学校"——采购和合规周期太长，6 个月内拿不到真实反馈。更适合作为 6 个月验证对象的是：教培机构、教培 SaaS、小型职教/素质教育机构。它们决策链更短，更容易给真实反馈。

公办 K12 听起来"大单稳定"，但 6 个月内根本走不完采购流程；教培机构小、决策快、敢用 AI——**beachhead 选错，整个 6 个月白干**。

## 12. 一个提醒

FDE 的核心不是"我会多少技术"，而是"我能不能在客户的混乱里交付价值"。6 个月准备过程中，每个项目都要站在"客户视角"想一遍：

- 这个项目如果是给 XX 学校/教育公司用，他们会关心什么？
- 部署成本、数据安全、家长接受度、教师负担——这些"非技术"问题是 FDE 面试官真正想听的。

把这点内化，offer 才有戏。

**v2 增补的最终画像**（ChatGPT 建议）：

> 一个能带着模型能力进入教育机构现场，把老师、学生、家长、校长、数据、系统、合规、成本揉成一个可上线方案的人。这才是 FDE。
